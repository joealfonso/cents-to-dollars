# M2.1 pipeline API (contract between engineer and test-writer)

Source of truth for behaviour is `specs/M2.md` sections 4.1 to 4.8. This file fixes names and shapes so tests and code can be written at the same time. Changing a signature here needs the main session.

## `src/take/` (shared, DOM-free and Node-free, imported by the Worker and by Node tools; F-29 applies)

```ts
// src/take/wav.ts
export interface ParsedWav { sampleRate: number; channels: number; samples: Float64Array } // samples = per-sample mean of channels, float64
export function parseWav(bytes: ArrayBuffer | Uint8Array): ParsedWav;           // throws TakeError('not-wav' | 'unsupported-format' | 'corrupt' | 'too-long'), too-long before allocating samples

// src/take/headers.ts
export function readMp3Rate(bytes: Uint8Array): number | null;                 // first valid MPEG audio frame, after any ID3v2 tag
export interface M4aRate { rate: number; confirmed: boolean }                    // confirmed false when implicit SBR is possible
export function readM4aRate(bytes: Uint8Array): M4aRate | null;
export type Container = 'wav' | 'mp3' | 'm4a' | 'unknown';
export function sniffContainer(bytes: Uint8Array): Container;                   // by magic bytes, not by file name

// src/take/mix.ts
export function mixToMono(channels: ArrayLike<number>[]): Float64Array;        // arithmetic mean per sample, in float64

// src/take/analyse.ts
export type TakeStatus = 'ok' | 'too-short' | 'no-pitch';
export interface VibratoWindow { t0: number; t1: number; rateHz: number | null; extentCents: number | null } // null = none found
export interface TakeResult {
  status: TakeStatus;
  sampleRate: number; hop: number; frameCount: number;
  t: Float64Array; start: Float64Array; voiced: Uint8Array;                    // plain-YIN voiced
  f0: Float64Array;                                                            // whole-take f0, 0 when unvoiced (decodeAll, lag Infinity)
  aperiodicity: Float32Array; rmsDb: Float32Array; eSf: Float32Array; eRef: Float32Array;
  specBins: number; spectrum: Float32Array;                                    // frameCount * specBins, row-major, power 0 to 4 kHz
  vibrato: VibratoWindow[];                                                    // VIB_WINDOW_S 2.5, VIB_STEP_S 0.5
}
export interface AnalyseOptions { onProgress?: (fraction: number) => void; shouldStop?: () => boolean }
export function analyseTake(mono: Float64Array, sampleRate: number, opts?: AnalyseOptions): TakeResult;
export function takeTransferables(r: TakeResult): ArrayBuffer[];               // every typed-array buffer in r, for postMessage transfer

// src/take/errors.ts
export class TakeError extends Error { code: string }

// src/take/cents.ts
export function centsSeries(f0: Float64Array, a4: number): Float64Array;       // NaN where f0 == 0; F-22
```

## Decisions recorded during the build (2026-11-09)

- **M4A and ADTS "rate not confirmed":** flagged only for AAC with a core rate of 24 kHz or less and no SBR or PS signalled. A higher core cannot carry implicit SBR, because HE-AAC output tops out at 48 kHz. This is narrower than the wording in spec 4.3: a 32 kHz AAC-LC file counts as confirmed.
- **Limits:** `MAX_DURATION_S` = 600, the longest tested duration that fit the placeholder budgets with this pipeline (`results/m2_take_memory.json`, spec 4.5 rule). `MAX_FILE_BYTES` is derived from it in the constants module. TakeError codes `too-long` and `too-large`.
- **Extra TakeError codes:** `unsupported-type`, `decode-failed`, `unsupported-rate`, `out-of-memory` (real allocation failures only), `cancelled`, `analysis-failed` (any other worker failure, including a worker that fails to load).

## `src/file/` (browser glue, may use DOM and Web Audio, not imported by Node tests)

- `decode.ts`: `decodeFile(file: File, signal?): Promise<DecodedFile>` with `DecodedFile = { input: TakeInput; transfer: ArrayBuffer[]; sampleRate: number; channels: number; rateSource: 'header' | 'resampled' | 'resampled-unknown' | 'not-confirmed'; nativeRate: number | null; durationS: number }`. Refuses a file over `MAX_FILE_BYTES` before reading it ('too-large') and a take over `MAX_DURATION_S` ('too-long') from the header where it can, else right after decoding (limits in `src/take/limits.ts`). WAV at 44.1 or 48 kHz: header read only (`readWavInfo`), `input` is `{ kind: 'wav', bytes }` and the Worker parses it with `parseWav`. MP3, M4A, ADTS AAC and other-rate WAV: rate from headers, decoded in an `OfflineAudioContext` at that rate when it is 44.1 or 48 kHz, otherwise at 48 kHz (Q1 Option B); `input` is `{ kind: 'channels', channels: Float32Array[], sampleRate }` and the Worker mixes them with `mixToMono`. `transfer` lists the buffers in `input`. The AudioBuffer is dropped before returning; `input` holds the only reference to the bytes or channels. No mono mix and no WAV parse on the main thread.
- `take.worker.ts`: receives a `TakeJob = { job } & TakeInput`, where `TakeInput` is `{ kind: 'wav'; bytes: ArrayBuffer } | { kind: 'channels'; channels: Float32Array[]; sampleRate: number } | { kind: 'mono'; mono: Float64Array; sampleRate: number }`, with its buffers transferred. Parses or mixes, then runs `analyseTake` in a later task so the message is unreachable during analysis. Posts `{ job, kind: 'progress', fraction }`, then `{ job, kind: 'result', result }` with `takeTransferables` (no structured-clone copies of the big arrays), or `{ job, kind: 'error', code, message }`. Error codes: a TakeError keeps its code; a failed big allocation (RangeError "Array buffer allocation failed" or "Invalid typed array length") is 'out-of-memory'; anything else is 'analysis-failed'.
- `client.ts`: `analyseFile(file, { onProgress?: (fraction, phase: 'decoding' | 'analysing') => void, onDecoded?: (info: DecodedInfo) => void, signal? }): Promise<AnalysedFile>` with `AnalysedFile = { job, fileName, fileBytes, sampleRate, channels, rateSource, nativeRate, durationS, result: TakeResult, timings: { decodeMs, analyseMs, totalMs } }`. Ties the two together with a job number, one Worker per job; starting a new job or aborting `signal` cancels the running one and terminates its Worker, and a cancelled job delivers no further progress or result. Every rejection is a `TakeError` with a code; a Worker that fails to load or crashes is 'analysis-failed'. `cancelAnalysis()` cancels the running job.

- **Addition (2026-11-09, approved by the main session, additive and optional):** `onDecoded` receives `DecodedInfo = { sampleRate, channels, rateSource, nativeRate, durationS }` (the same values `AnalysedFile` later carries) once decoding finishes and before the Worker starts. It is not called for a job that was cancelled during decoding. The take view uses it to fill the file strip and the first Analysing announcement during Analysing (M2-DESIGN.md 3.3). No existing signature or behaviour changed.

## Node runner

- `node tools/run_ts.ts take <wav|dir> <out_dir>`: reads with `parseWav`, runs `analyseTake`, writes JSON with frames, f0 and vibrato windows (V-02).
